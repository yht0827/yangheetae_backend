# 기능 요구사항

## 1. 계좌 관리

- 새로운 계좌를 등록하여 계좌 정보를 생성할 수 있어야 한다.
- 기존 계좌를 삭제(soft delete)할 수 있어야 한다.
- 삭제된 계좌는 조회/거래 대상에서 제외되어야 한다.

## 2. 입금

- 특정 계좌에 금액을 입금하여 잔액을 증가시킬 수 있어야 한다.
- 금액이 0 이하인 경우 요청은 실패해야 한다.
- 입금 내역은 거래 내역(`DEPOSIT`)으로 저장되어야 한다.

## 3. 출금

- 특정 계좌에서 금액을 출금하여 잔액을 감소시킬 수 있어야 한다.
- 금액이 0 이하인 경우 요청은 실패해야 한다.
- 잔액이 부족한 경우 출금은 실패해야 한다.
- 출금 내역은 거래 내역(`WITHDRAWAL`)으로 저장되어야 한다.
- 일 한도: 1일 최대 1,000,000원
  - 한도 초과 시 출금은 실패해야 한다.
  - 한도 검증은 `daily_usages.withdrawal_total_won`을 기준으로 수행한다.

## 4. 이체

- 출금 계좌에서 다른 계좌로 금액을 이체할 수 있어야 한다.
- 동일 계좌로는 이체할 수 없어야 한다.
- 금액이 0 이하인 경우 요청은 실패해야 한다.
- 이체 시 출금 계좌 잔액은 `(이체 금액 + 수수료)` 만큼 감소해야 한다.
- 이체 시 수취 계좌 잔액은 `이체 금액` 만큼 증가해야 한다.
- 수수료: 이체 금액의 1% (원 단위 정수, 소수점 처리는 정책에 따른다)
- 이체 내역은 아래 항목으로 거래 내역에 저장되어야 한다.
  - 출금 계좌: `TRANSFER_OUT` 및 `FEE`
  - 수취 계좌: `TRANSFER_IN`
- 위 거래 내역은 동일한 `related_transfer_id`로 묶여 추적 가능해야 한다.
- 일 한도: 1일 최대 3,000,000원
  - 한도 초과 시 이체는 실패해야 한다.
  - 한도 검증은 `daily_usages.transfer_total_won`을 기준으로 수행한다.

## 5. 거래 내역 조회

- 지정된 계좌의 입금/출금/이체(송금/수취) 내역을 조회할 수 있어야 한다.
- 거래 내역은 최신순으로 정렬되어 반환되어야 한다.
- 페이징 또는 기간 필터를 제공할 수 있어야 한다.
